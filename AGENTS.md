# Project agreements

- Viblio lives in its own standalone repository (`Valtecir-C-Heckert/Viblio`), completely independent from the Central app (`Valtecir-C-Heckert/Home-assistant`). Keep Viblio APKs, storage, IDs (`br.com.viblio`) and releases independent.
- Treat security as a requirement in each implementation: enforce server-side authorization and account isolation; bound inputs, files, decompression, resource use and request rates. Never log or publish passwords, tokens, personal data or `.env`. Preserve TLS checks. Validate relevant abuse cases and data-loss risks.
- Normal users use accounts and automatic offline/online synchronization. Manual JSON file import/export is an administrator tool in Viblio. Internal JSON sync transport is allowed. Never silently overwrite unresolved conflicts or newer local edits.
- Login appears at startup without a session. Account is profile/logout/admin functions. Personal Home Assistant credentials must not be exposed to invitees. No KOReader integration without a new request.
- User's API update workflow: locate the new ZIP (downloaded via GitHub Release or Nextcloud); back up database, covers/private snapshots and `.env`; copy ZIP to `/tmp`, verify and extract as the non-root server user into `/opt/viblio/api`, preserving `.env`. Confirm each migration exists before running it. Rebuild using `docker compose -p viblio-catalog-api -f compose.api.yaml`, then check healthy. Never `down -v`, rerun configure.py or replace `/opt/viblio/compose.yaml` for an update.
- Debian resources: PostgreSQL `viblio-postgres`; db/user `viblio`; API `viblio-catalog-api-viblio-api-1`; persistent volume `viblio-catalog-api_viblio-covers`. Optional Nextcloud ZIP directory is configured via `VIBLIO_NEXTCLOUD_DIR` (default `/DATA/AppData/nextcloud/var/www/html/data/<usuario>/files/`). Test only disposable databases named `viblio_test*` and Android emulators, never personal data/devices.
- Deliver release APKs with debugging disabled. Preserve the Android signing certificate and existing account/library IDs. Update documentation and deliver matching APK/API packages with checksums and tested install instructions. State clearly which server protections require deployment outside this repository.
- API update helper: keep published migrations immutable and include their complete history in future ZIPs. Add new migrations as additive/repeatable files, publish ZIP SHA-256 in downloads/SHA256SUMS, and retain the stable Compose project/service/volume contract. The standalone updater lives outside /opt/viblio/api; see viblio-api/UPDATER.md. Never replace an already published version ZIP just to add the helper.
- Keep Viblio screens concise: do not add explanatory helper paragraphs about sync, privacy or how controls work. Keep labels, useful empty states and actionable error messages.
- Viblio reading backgrounds follow the opened book, including non-current books: retain each cover enlarged and darkened behind its reading screen. General tabs follow the current book; do not remove other books’ cover backdrops or change cards/text/highlights when adjusting only backgrounds.
- In Viblio cover shelves, hide printed book titles at every zoom and retain accessibility names; keep spine titles/authors. Reading card surfaces follow the opened book’s own cover. Statuses are Não iniciado, Pausado, Lendo and Concluído; never use Pronto for reading state.
- Forward page-bar changes offer timed reading registration and an explicit page-only correction. Commit session/progress atomically; preserve timer drafts and history on cancellation/correction. Friends/search consultation views must never modify a friend’s library; leaving the Friends tab resets to its list.
- Personal goals live in Statistics as one wholly collapsible section, initially closed. Keep the distinct circle/book, digit/page and purchase-cycle counters. Goals are private per account, synchronized through opaque SHELF_READING_GOAL preferences; do not expose goals/receipts to friends. Purchases consume unique completed books once per goal and preserve cycle receipts.
- Goal visuals must follow the approved compact Statistics sketch: one continuous surface with thin dividers, small headings, a circle beside the remaining count and narrow page-counter digits. Do not introduce large separate goal cards, full-width digit tiles or large explanatory/action blocks. Check the actual full Statistics screenshot, not only the isolated section.
- Automatic sync must retain attempts blocked by busy operations and resume them after completion; preserve local edits, profile isolation, draft/form guards and explicit conflict resolution. Friends current-page refresh runs only while visible, at a bounded interval with retry backoff, preserving loaded pages/filters/scroll and rejecting stale profile/navigation responses. Purchase goals may use a small reward ticket and actual credited covers within the continuous goals section.
- In book detail, Seu ritmo highlights the sum of saved session durations for that book and retains average time per page. Use Tempo total de leitura while unfinished and Tempo para concluir after completion; show — without sessions. Do not substitute calendar days, page estimates or an unsaved draft for registered time.
- SHELF_SPINE_ZOOM is local to each device/profile: exclude only this key from account capture/hash/apply and preserve it through restores. Resolve only its exact legacy conflict path automatically, with bounded retries and the server revision. Never auto-choose progress, book, manual-order or goal conflicts; show only substantive conflicts in the decision dialog. Recheck stale legacy conflict markers on a new account session without repeatedly retrying a confirmed data conflict while the user is deciding.

- Friends has Feed, Meus amigos and Clubes. Directory reveals usernames only; friendship still requires acceptance. Since 0.4.1 readings share automatically with accepted friends, with no switch/confirmation; never publish notes/goals or indiscriminately backfill old history. Club membership and roles are independent per club; invites require acceptance, several admins may coexist, transfers are atomic and removal/demotion/leave must retain at least one admin. Group progress and manual admin date adjustments must not silently change private reading progress or schedules.
- Social visual follows the approved dark outlined-card Feed reference. Feed and club list inherit the owner’s current-book palette. Inside a club, use a local palette from its selected reading book’s cover, including discussions; restore the owner’s palette on exit and never modify the global book theme. Catalogue covers use a three-column grid with edition metadata, selection and pagination preserved.
- Book Seu ritmo keeps total saved duration prominent on the left and per-page average on the right. Saved history sessions can edit assigned day/duration or be deleted with confirmation; preserve book progress, active timer, IDs and original timestamps. Verify expected session before destructive writes, recalculate derived totals and sync edits/deletes. Track history dialogs to block library replacement and close them on profile teardown.

- Club main page is the reading hub, with deadline, selected cover, stages/comments and a feed scoped to the round/book. Admin settings go in ⋯, separate from the main page. Completed readings live in group History with their covers/stages/discussions. Book voting candidates can be selected from every active member’s synchronized shelf via a bibliographic allowlist, without granting private-library access. Each general-feed card follows that event’s cover palette and uses separate left/right metrics for pages and time.

- The owner confirmed the colleague’s loading incident was his Internet connection and authorized moving forward with 0.4.2. The source-only release hold is lifted. Keep the separate FriendsPanel loading/session lifecycle correction and live comments; do not describe that correction as the cause of the colleague’s network incident.
- Live discussion comments use authenticated SSE notifications and persisted message reads, preserve composer/draft/focus/scroll, stop on navigation/profile changes, and recheck session/membership/discussion access. Bound streams independently from ordinary request slots. The event bus supports the documented single-worker API; shared notifications are required before adding workers.

- Deliver Viblio downloads consistently through the existing GitHub Release attachments. Publish and verify the download-ready marker before sending release URLs; never substitute internal /workspace paths or unverified raw/blob URLs as user download links. Include the server commands with API updates.

- Social reads use a bounded 12-second call budget (writes 30), independent of backup/sync transfers. Cancel queued request handles as well as running calls on navigation/session reset; never let an obsolete queued read delay the active tab. Pending social reads use the refresh indicator, not loading paragraphs; invalid list responses are errors, not empty shelves. Keep diagnostics free of tokens and personal data.

- Launcher sizing requests refer to the book drawing inside the app's home-screen icon. Preserve the tile/background, outer size and internal navigation symbols. Validate rendered proportions at multiple sizes rather than claiming a percentage from dp insets around a large nodpi bitmap.

- After using Viblio's page slider, let the user edit the destination page before saving. Both timed registration and page-only correction use that edited value; backward corrections also require confirmation. Validate the page without dismissing invalid forms; cancellation preserves progress/history and timer drafts.
